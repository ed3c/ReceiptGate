No proof.
No action.

當 autonomous agent 開始替人下單、付款、呼叫另一個 agent 或觸發真實 side effect，最大的風險不是模型不夠聰明，而是「誰授權、哪個版本被批准、證據是否綁定到同一個候選動作」沒有被機械化驗證。

Execution invariant execute(sideEffect) is unreachable unless verify(proof, candidate) == PASS AND policy(candidate) == ALLOW

為什麼 ReceiptGate 必要

LLM 可以提出動作，但不能因為「看起來合理」就自動取得執行權。ReceiptGate 把推理、證明與授權拆成三個不同的 trust boundary。

MODEL

What intelligence generated this?

Agent A / Agent B 可以提出候選與風險建議，但模型輸出只是 proposal，不是 authority。

PROOF

What can I independently verify?

Wallet signature、candidate hash、handoff binding、runtime receipt、Agentic ID / ServeProof 都必須能被獨立驗證。

POLICY

Is that evidence enough to execute?

Deterministic policy 決定證據是否足以讓 side effect reachable。模型不能選擇自己的 authority。

Compute proposes; Proof verifies; Policy authorizes.
這就是 ReceiptGate 與一般「Agent + tool call」最大的差異。
